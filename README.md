# RAG Assignment: Baseline Retrieval vs. Cross-Encoder Re-Ranking

A comparison of two retrieval pipelines over the same document corpus:

| | Pipeline 1 (Baseline) | Pipeline 2 (Re-ranking) |
|---|---|---|
| Stage 1 | Bi-encoder → FAISS cosine search → top 10 | *identical* |
| Stage 2 | — | Cross-encoder scores all 10 `(query, chunk)` pairs |
| Selection | first 3 of the top 10 | top 3 after re-sorting |
| Generation | shared prompt | shared prompt |

The only variable between the two answers is the ordering of the final three chunks.

## Document

**Magic: The Gathering Comprehensive Rules**, effective 7 June 2024 — 292 pages.

- Source: <https://media.wizards.com/2024/downloads/MagicCompRules%2020240607.pdf>
- The PDF is not committed to this repo; download it into the project root as
  `MagicCompRules.pdf` before running the notebook.

It was chosen because it is dense with prohibitions ("can't", "may not"), exceptions
("except", "unless"), and repeated terminology — the exact conditions that make dense
retrieval fail.

## Models

| Component | Model |
|---|---|
| Bi-encoder | `sentence-transformers/all-MiniLM-L6-v2` |
| Cross-encoder | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| Vector index | FAISS `IndexFlatIP` over L2-normalised embeddings (inner product = cosine) |
| LLM | `google/gemini-2.5-flash` via OpenRouter, `temperature=0` |

## Chunking

Rule-aware rather than character-based: the PDF is parsed into numbered rules
(`701.17a`, `704.5j`, …), table-of-contents pages are dropped, PDF line-wrap artefacts are
repaired, and consecutive rules are packed into chunks of ~700 characters (hard cap 1,100)
with one rule of overlap.

Result: **1,937 chunks**, average 642 characters, maximum 1,099 — comfortably under the
cross-encoder's 512-token limit.

## Running

```bash
pip install -r requirements.txt

# The API key is read from the environment and never stored in the notebook.
export OPENROUTER_API_KEY="sk-or-..."

jupyter notebook RAG_Assignment.ipynb
```

Then run all cells top to bottom. The notebook writes `chunks.json` on first run so chunk IDs
stay stable.

## Failure queries

Gold chunks are annotated by **rule number** and resolved programmatically, so the
annotation is reproducible rather than hand-copied. The query set covers all four required
categories plus one honest negative control where re-ranking does not help.

## Notes

- `temperature=0` so differences between Answer 1 and Answer 2 come from the retrieved
  context, not from sampling.
- Both pipelines call the same `retrieve_top_k()` and the same `PROMPT_TEMPLATE` constant.
- The report is written separately and is not generated by the notebook.
